# 消防小本本：安裝、設定與使用手冊

本手冊對應 `Code.gs` 與 `Index.html`。系統供你自己的 Gmail 帳號使用：試算表、案件附件、Google Tasks 清單與自動備份都放在同一個 Google 帳號下。依序完成下列步驟後，使用私人 `/exec` 網址開啟。

程式頁面標題、新建試算表名稱、每月備份檔名與本手冊均使用「消防小本本」。工作表仍名為 `業務公文管理`，Tasks 清單仍名為 `消防`，這兩個是資料識別名稱。

> **建議先用空白資料建立新系統。** 第一次初始化會建立試算表與資料夾，並建立 Tasks 清單及每月備份觸發器。不要先拿含有其他資料的試算表或 Drive 資料夾測試。

## 1. 系統會建立什麼

- **GAS 網頁程式**：`Code.gs` 負責 Sheets、Drive、Tasks 與分頁 API；`Index.html` 是手機與電腦共用的單頁介面。
- **Google 試算表**：主工作表 `業務公文管理` 儲存案件；隱藏工作表 `_系統索引` 保存資料 ID、目前列號、案件資料夾 ID 和 Tasks 任務 ID；隱藏工作表 `_操作紀錄` 保存短期請求冪等狀態。主表維持原本 10 欄。
- **Google Drive**：你指定一個母資料夾，每案建立一個子資料夾；母資料夾中也會有 `_系統備份`。
- **Google Tasks**：自動尋找或建立名為 `消防` 的清單。
- **私人 Web App**：以部署者的 Google 權限執行，且限制只有你的帳號可以開啟。

系統目前不提供離線使用、背景同步、刪除案件按鈕或附件備份。主畫面捷徑仍需要網路；每月備份只複製試算表，不複製 Drive 案件附件。

## 2. 部署前準備

請先用**同一個個人 Gmail 帳號**完成以下準備；後續 Apps Script 初始化、部署、手機登入都要使用這個帳號。

### 2.1 建立 Drive 母資料夾並取得 ID

1. 開啟 [Google Drive](https://drive.google.com/)，確認右上角是預定使用的 Gmail 帳號。
2. 按「新增」→「新增資料夾」，例如命名「消防案件附件」。
3. 開啟新資料夾，網址大致為 `https://drive.google.com/drive/folders/資料夾ID`。
4. 複製 `/folders/` 後面那串 ID。只複製 ID，不要複製整條網址。
5. 暫時不要把母資料夾分享給其他人；個人版部署不需要額外分享。

### 2.2 決定試算表方式

- **新手建議：使用新試算表。** 稍後將 `SPREADSHEET_ID` 留空，`setupSystem()` 會建立試算表並記住 ID。
- **使用既有試算表：** 需提供試算表網址中 `/d/` 和 `/edit` 之間的 ID。若其中已經有 `業務公文管理` 工作表，第一列 10 個欄名必須與本手冊第 8 節完全一致。程式不會替既有錯誤欄名自動改名。
- 不要使用含有其他重要資料的工作簿；系統會新增或調整工作表與欄寬。

## 3. 建立 Apps Script 專案並放入程式

1. 開啟 [Apps Script](https://script.google.com/)，確認登入的是剛才建立 Drive 母資料夾的 Gmail。
2. 按「新專案」。在左上角將專案命名為「消防小本本」。
3. 左側開啟 `Code.gs`，刪除範例內容，貼上交付的 `Code.gs` 全文並儲存。
4. 左側按「＋」→「HTML」，名稱輸入 `Index`（不要輸入 `.html`），貼上 `Index.html` 全文並儲存。檔案名稱必須剛好是 `Index`，因為 `doGet()` 會載入它。
5. 在 `Code.gs` 最前方設定母資料夾 ID：

   ```js
   const ROOT_FOLDER_ID = "貼上你的Drive母資料夾ID";
   ```

   不要保留 `YOUR_FOLDER_ID`，也不要刪除引號。

6. 若要新建試算表，保留：

   ```js
   const SPREADSHEET_ID = "";
   ```

   若使用既有試算表，才填入其 ID。

7. 左側開啟「專案設定」，確認時區為 **(GMT+08:00) Taipei**。程式日期格式也使用 `TIME_ZONE = "Asia/Taipei"`，兩者都應維持台北時區。
8. 在「專案設定」確認 Apps Script 使用 **V8 執行環境**。新建專案通常已設定 V8；若查看 manifest，`runtimeVersion` 應為 `V8`。
9. 按「儲存專案」。不要把 `Code.gs` 貼進 HTML 檔，也不要把 HTML 貼進 `Code.gs`。

## 4. 設定 Google Tasks API

### 4.1 在 Apps Script 加入進階服務

1. Apps Script 左側找到「服務」，按右側「＋」。
2. 搜尋並選擇 **Google Tasks API**，版本選 `v1`，按「新增」。
3. 確認左側服務清單出現 `Tasks`。程式中的呼叫名稱就是 `Tasks`。

這是本系統必要設定。未加入時，案件建檔仍可能成功，但 Tasks 功能會出現「尚未啟用」錯誤。

### 4.2 Cloud API 是否要另外開啟

- 若使用 Apps Script 自動建立的**預設 Cloud 專案**，在上一步新增進階服務時，Google 會自動處理對應 API。
- 若你曾把 Apps Script 專案改綁**標準 Google Cloud 專案**，請在該 Cloud 專案的「API 和服務」中啟用 **Google Tasks API**；此程式使用 `DriveApp`，標準專案也需啟用 **Google Drive API**。
- 試算表由 Apps Script 內建的 `SpreadsheetApp` 操作，不需為此另外加 Google Sheets 進階服務。
- 這個系統不需要啟用 Apps Script API。單人個人使用建議保留預設 Cloud 專案，避免不必要的 Cloud 設定。

通常不需要手動編輯 `appsscript.json`。若你選擇用 manifest 設定服務，服務項目的內容應為 `userSymbol: "Tasks"`、`serviceId: "tasks"`、`version: "v1"`；只把它加進既有的 `dependencies.enabledAdvancedServices`，不要整份覆蓋 manifest。官方提醒錯誤的 manifest 可能阻止儲存版本部署。

## 5. 第一次初始化及授權

1. Apps Script 編輯器上方函式選單選 `setupSystem`。
2. 按「執行」。第一次執行會要求登入及授權；選擇部署用 Gmail，檢查授權畫面列出的 Google 服務，按允許。
3. 依程式內容，授權範圍會涵蓋建立／讀寫試算表、Drive 資料夾與附件、Google Tasks，以及安裝每月備份、每日操作紀錄清理和快取失效觸發器。Apps Script 會依程式使用的服務決定授權項目。
4. 執行完成後，檢查執行記錄與 Google Drive，應可找到：
   - 名稱為 `消防小本本` 的試算表（使用新試算表時）。
   - 試算表內的 `業務公文管理` 工作表，第一列是 10 個欄名。
   - 隱藏的 `_系統索引` 與 `_操作紀錄` 工作表。
   - 母資料夾內的 `_系統備份` 資料夾。
   - Google Tasks 中的 `消防` 清單。
5. 若要確認試算表網址，可在 Drive 開啟試算表；初始化函式的執行結果也會回傳試算表網址和母資料夾網址。若結果中的 `metadataTriggerWarning` 有訊息，初始化仍已完成；直接在試算表手動編輯後，中繼資料快取最久可能延遲 60 秒更新，Web App 自身的寫入仍會立即更新快取版本。

**授權畫面顯示「未經 Google 驗證」時：**先確認你正在執行自己建立的 Apps Script 專案、網址是 Google 官方網域，授權帳號正確，且授權項目符合上列用途。若畫面顯示的專案或權限讓你無法確認，先取消並檢查程式，不要繼續。這是個人專案；不要把部署存取權改為所有人來繞過登入問題。

## 6. 測試部署及正式部署

### 6.1 先做編輯器測試

1. 儲存目前程式後，在右上角選「部署」→「測試部署作業」。
2. 部署類型選「網頁應用程式」，複製測試網址並開啟。
3. 測試網址通常以 `/dev` 結尾，只供有 Apps Script 專案編輯權的人使用，且會執行最新已儲存程式。它適合自己開發測試，不是給手機長期使用的正式網址。
4. 確認畫面可載入，新增一筆測試案件後檢查試算表、Drive 案件資料夾和 Tasks。測完可在試算表刪除測試列、在 Drive 移除測試資料夾、在 Tasks 刪除測試任務。

### 6.2 建立正式私人部署

1. 按「部署」→「新增部署」。
2. 「選取類型」按齒輪，選 **網頁應用程式**。
3. 說明可填「個人使用」。
4. **執行身分：我（部署者）**。這會讓 Apps Script 以你的帳號使用 Sheets、Drive 與 Tasks。
5. **誰可以存取：只有我自己**。不要選「任何人」或「任何知道連結的人」。
6. 按「部署」，如系統再次要求授權，選同一個 Gmail 帳號並完成授權。
7. 複製以 `/exec` 結尾的網址，先在電腦瀏覽器中開啟並登入部署帳號。

部署設定要同時符合「以我執行」和「只有我自己可存取」。前者決定程式用誰的 Google 權限，後者限制誰能打開網頁。若登入多個 Google 帳號，建議在瀏覽器個人檔案切換至正確 Gmail，或用私人瀏覽視窗登入該帳號再開 `/exec`。

### 6.3 修改程式後更新正式版

1. 在 Apps Script 編輯器修改 `Code.gs` 或 `Index.html`，按「儲存」。
2. 選「部署」→「管理部署作業」。
3. 找到現有網頁應用程式部署，按鉛筆「編輯」。
4. 版本選「新增版本」，輸入簡短說明，按「部署」。
5. 繼續使用原本 `/exec` 網址；不需要每次新增另一個正式部署。
6. 手機如果還顯示舊畫面，先重新載入網頁；若仍舊，關閉主畫面捷徑後重新開啟。

## 7. iPhone 與 Android 加到主畫面

### iPhone：Safari

1. 在 iPhone 開啟 **Safari**，用部署用 Gmail 登入，再開正式 `/exec` 網址。
2. 點「分享」圖示。
3. 在分享選單選「加入主畫面」；若沒有看到該項目，往下找「編輯動作」並加入。
4. 編輯顯示名稱後，開啟「以網頁 App 打開」（若畫面有此選項），按「加入」。
5. 從主畫面圖示開啟。第一次仍需網路及 Google 登入授權。

### Android：Chrome

1. 在 Android 開啟 **Chrome**，用部署用 Gmail 登入，再開正式 `/exec` 網址。
2. 點網址列旁的「⋮」選單。
3. 選「安裝並建立捷徑」→「建立捷徑」→「新增」。選單文字可能隨 Chrome 版本略有不同。
4. 從主畫面圖示開啟，必要時重新登入部署用 Gmail。

這個專案目前是**需要網路的 Web App 捷徑**，沒有離線快取、Service Worker 或離線資料庫。iOS 的「以網頁 App 打開」只改變開啟方式，不會讓系統離線運作。

## 8. 系統資料與設定說明

### 8.1 `Code.gs` 可調整的設定

| 設定 | 目前值 | 用途與注意事項 |
|---|---|---|
| `ROOT_FOLDER_ID` | `YOUR_FOLDER_ID`（需替換） | Drive 母資料夾 ID；填 ID，不填整條網址。 |
| `SPREADSHEET_ID` | 空字串 | 空白時首次初始化自動建立試算表；亦會把實際 ID 存入 Script Properties。 |
| `DATA_SHEET_NAME` | `業務公文管理` | 案件資料工作表名稱。 |
| `INDEX_SHEET_NAME` | `_系統索引` | 隱藏的 ID、列號、資料夾與 Tasks 關聯表。不要手動刪除或改欄名。 |
| `OPERATION_SHEET_NAME` | `_操作紀錄` | 隱藏的短期冪等操作表；每次寫入及每日觸發器會清理。不要手動刪除或改欄名。 |
| `TASK_LIST_TITLE` | `消防` | 自動定位或建立的 Tasks 清單名稱。 |
| `TIME_ZONE` | `Asia/Taipei` | 顯示及儲存日期所使用的時區。Apps Script 專案時區也要設台北。 |
| `MAX_UPLOAD_BYTES` | 5 MiB | 建檔或更新的附件原始位元組合計上限。圖片會嘗試轉成最長邊 1600px、JPEG 品質 0.75；HEIC/HEIF 無法轉成 JPEG 時會阻止送出。 |
| `MAX_HISTORY_CHARS` | 50,000 字元 | 單一案件 H 欄時間軸上限；超限前會拒絕儲存，不會先上傳附件。 |
| `RECORD_PAGE_SIZE` | 60 | 每次從試算表載入的案件數。 |
| `TASK_PAGE_SIZE` | 50 | Tasks 抽屜每次載入數量。 |
| `MAX_REQUEST_JSON_BYTES` | 6 MiB | 包含 Base64 與欄位內容的整包 JSON 上限；前後端都會檢查，超過時前端會提示「檔案合計過大，請分批上傳或只留重點附件」。 |
| `REQUEST_CACHE_TTL_SECONDS` | 600 秒 | 已完成請求結果的短期快取；耐久冪等狀態仍以 `_操作紀錄` 為準。 |
| `OPERATION_RETENTION_DAYS` | 7 天 | 自動清除過期操作紀錄。 |
| `MAX_OPERATION_ROWS` | 1,000 筆 | 新操作即將超過上限時才修剪紀錄；過期資料由每日觸發器清理。容量修剪會優先保留最近更新的紀錄。 |
| `TASK_COUNT_CACHE_TTL_SECONDS` | 60 秒 | 未完成 Tasks 數量快取；系統內的新增、完成、重開和刪除會增量更新。 |
| `METADATA_CACHE_TTL_SECONDS` | 60 秒 | 中繼資料快取期限；Web App 寫入會換版本，試算表人工編輯和列結構變動由安裝型觸發器盡快失效。讀取卡片時另外以當前 A 欄建立資料 ID 到列號的對照，避免快取列號在排序後錯位。 |
| `MAX_BACKUP_FILES` | 24 份 | `_系統備份` 僅保留最近 24 份月備份；建立新備份後，較舊副本會移至 Drive 垃圾桶。 |

若調整欄位名稱、Tasks 清單名稱或工作表名稱，必須同時理解並修改前後端程式中的相關邏輯；單改常數不一定能遷移既有資料。

### 8.2 主工作表 10 欄

`業務公文管理` 第一列欄名須依序為：

| 欄 | 欄名 | 程式用途 |
|---|---|---|
| A | 資料ID | 系統產生 `DOC-YYYYMMDD-序號`，用於精準定位。 |
| B | 發文/登記日期 | 案件日期，顯示格式 `YYYY-MM-DD`。 |
| C | 標籤類別 | 公文、訓練、耗材、器材或自訂標籤。 |
| D | 案件/公文主旨 | 卡片與 Tasks 標題。 |
| E | 內容說明 | 長文字說明。 |
| F | 限辦/完成期限 | 可空白；同步至 Tasks 的 due 日期。 |
| G | 執行狀態 | 待辦、辦理中、已結案、存查。 |
| H | 執行進度與摘要 | 最新紀錄置頂；整格最多 50,000 字元。 |
| I | 專屬資料夾連結 | 每案 Drive 子資料夾。 |
| J | 建檔時間 | 初次建立時寫入，顯示至秒。 |

新增案件時程式會建立子資料夾，名稱格式為 `[標籤]_[日期]_[主旨]`；首次附件前綴為 `[原件]_`，後續附件前綴為 `[進度_MMdd_HHmm]_`。同一批附件若有同名檔案，會加上序號（例如 `[原件_1]_image.jpg`、`[原件_2]_image.jpg`）；若資料夾已有同名檔案，也會自動加序號避免混淆。在進度視窗修改標籤、日期或主旨時，系統也會同步更新案件資料夾名稱；若同名，會在資料夾名稱加上資料 ID 避免衝突。

### 8.3 Script Properties 的試算表 ID

第一次新建試算表時，程式會把試算表 ID 存到 Apps Script 的 Script Properties。之後這個已儲存的 ID **優先於** `SPREADSHEET_ID` 常數；只改常數不會讓既有專案改用另一份資料庫。

若真的要切換或還原資料庫：先備份目前試算表，再到 Apps Script「專案設定」→「指令碼屬性」，確認 `SPREADSHEET_ID` 的值並更新為目標試算表 ID。儲存後重新載入 `/exec`；中繼資料快取依試算表 ID 分開，不會把舊工作簿快取混到新工作簿。先核對資料再繼續使用。不要刪掉或改名案件資料夾；試算表 I 欄及索引會連到原 Drive 子資料夾。

### 8.4 主要效能行為

- 首頁先載入未結案案件和最近 90 天案件的首批 60 筆；按「載入更多案件」可繼續分頁。
- 年度歷史庫需手動開啟，按年度載入；切換年度會移除先前載入的歷史年度，降低手機記憶體用量。若收合或切換時尚有讀取中的舊請求，回應會依年度載入版本丟棄，不會把已卸載資料放回畫面。
- 點擊「收合年度選單」會卸載目前選取的歷史年度，清除年度選擇並返回目前案件視圖。
- 搜尋和狀態數字涵蓋**目前已載入**案件。先載入更多或指定歷史年度，再搜尋該批資料；完整舊時間軸只在開啟進度視窗時讀取。
- 案件卡片與後端分頁使用相同優先順序：待辦／辦理中先載入，依期限由近到遠，無期限者依建檔時間由新到舊；已結案／存查依發文日期及建檔時間由新到舊。因此首頁首批資料不會被近期已結案案件擠掉未結案急件。
- 新增案件的預設日期與「近 90 天」判斷固定使用 `Asia/Taipei`；即使手機所在時區不同，午夜前後也會與後端一致。空白工作表會回傳空案件清單、空年度清單及空游標；建立第一筆後即可照常搜尋、分頁和載入歷史年度。
- 卡片資料依實際列號每 300 列為一個區塊讀取；資料列分散時不會為每張卡片拆成多次欄位讀取。
- 卡片一次最多新增顯示 40 張；Tasks 面板在第一次開啟時讀取，每次最多 50 筆。
- Apps Script 與 Google 服務有執行時間、配額和頻率限制；配額會變更，遇到大量批次或 API 錯誤時查看執行記錄及官方配額頁，不要直接對正式資料做大型壓力測試。

## 9. 日常操作與資料保護

### Tasks 與案件狀態的同步方向

- 新建案件時「同時加入 Tasks」預設勾選；可在建檔視窗取消。
- 新建案件時直接建立 Google Tasks 任務，不會為新資料 ID 掃描整份歷史 Tasks 清單；只有斷線復原或卡片手動同步且索引缺少任務 ID 時，才會以資料 ID 搜尋既有任務。
- 卡片的「同步到 Tasks」會建立或更新該案關聯任務；任務標題為 `【標籤】主旨`。
- 在案件進度視窗展開「修改案件基本資料」可編輯日期、標籤、主旨、期限及內容說明；修改標籤／日期／主旨會同步重新命名 Drive 子資料夾，修改標籤／主旨／期限會更新已連結 Tasks 的標題與期限。
- 開啟案件進度視窗時，系統會先載入完整時間軸與內容說明；載入成功前「儲存更新」會鎖定。若載入失敗，關閉視窗後重新開啟即可重試。
- 「全文手動修改」可只修正歷史文字並直接儲存，不必額外新增一筆進度；若同時輸入新進度、變更狀態或上傳附件，該筆新紀錄仍會置頂。
- 案件改為「已結案」會將關聯 Tasks 任務完成；案件從已結案改回其他狀態會重新開啟關聯任務。
- 若限辦期限空白，新建 Tasks 任務會省略 due 欄位；清除既有案件期限時，會透過更新請求清除該 Tasks 任務的期限。
- 在 Tasks 勾選完成**不會**反向將案件改為已結案。抽屜也會提示：「勾選僅完成 Google Tasks 待辦提醒；案件結案請至案件卡片更新進度」。
- Tasks 的 due 欄位帶入日期，不會建立額外提醒通知。

### 備份與還原

- `setupSystem()` 建立每月一次的觸發器，在每月 1 日約凌晨 3 點執行試算表副本備份；Apps Script 時間觸發器可能在指定時段內稍後執行，不保證剛好 03:00。
- 備份放在母資料夾的 `_系統備份`，檔名為 `消防小本本備份_YYYY-MM`，包含案件主表、隱藏索引和操作紀錄；**不包含案件 Drive 子資料夾及附件**。
- 最多保留依建立時間排序的最近 24 份月備份；超過上限的舊備份會移到垃圾桶，可在 Drive 垃圾桶中復原。若需要長期保留特定版本，請在下次清理前將該副本移出 `_系統備份` 或另外複製保存。
- 定期打開 `_系統備份` 確認副本有生成。也建議偶爾在 Drive 下載或另行複製試算表，避免只有一種備份位置。
- 還原前不要覆蓋現有資料。建立備份副本後，依前節更新 Script Properties 中的 `SPREADSHEET_ID`，先核對資料及資料夾連結，再繼續使用。還原舊試算表不會自動還原已刪除的 Drive 附件。
- `setupSystem()` 會重建本專案的月備份、每日操作紀錄清理及試算表編輯／變更快取失效觸發器。每日清理也會刪除 `_系統索引` 中主表已不存在的孤兒資料 ID。快取失效觸發器屬最佳化；若它們安裝失敗，初始化仍會完成，回傳結果會顯示 `metadataTriggerWarning`，並以 60 秒快取期限作為後備。

### 手動編輯試算表的注意事項

- 不要刪除或重新命名 `_系統索引`，也不要修改其欄位；否則程式可能找不到任務或資料夾關聯。
- 主表若需排序，請對整個資料範圍排序，不要只排序單一欄，否則欄位會對錯案件。
- 透過 Web App 輸入以 `=`、`+`、`-` 或 `@` 開頭的文字時，程式會加上純文字保護；讀回時會移除這個保護用字元，避免它出現在畫面或反覆編輯時疊加。直接在試算表輸入時仍請自行以文字格式輸入。
- 分頁游標使用案件狀態、期限／日期、建檔時間與資料 ID 的排序鍵，另保留建檔快照界線；不依賴列號。案件更新仍會先用資料 ID 驗證目前列號。一般整列排序可以定位，請勿改資料 ID 或只排序單一欄。
- 直接在表格編輯日期、狀態或主旨時，安裝型觸發器會更新快取版本；若觸發器未安裝或延遲，欄位內容可能最多受 60 秒快取期限影響。列號對照會在讀取時以資料 ID 重建。重要欄位以資料 ID 對應，不要修改資料 ID 或建檔時間。
- 不要在 Apps Script 專案中貼出或分享 OAuth 權杖、瀏覽器密碼或其他憑證；此專案不需要你提供這些資料。

## 10. 常見問題排除

### `尚未啟用 Apps Script 的 Tasks API 進階服務`

回到 Apps Script 左側「服務」，確認有 `Tasks`；若是標準 Cloud 專案，再確認該 Cloud 專案已啟用 Google Tasks API。新增服務後儲存，再執行一次 `setupSystem()`。

### `請先設定 ROOT_FOLDER_ID` 或建立資料夾失敗

確認常數不是 `YOUR_FOLDER_ID`、只貼 ID 沒有多餘空白，而且母資料夾仍存在於同一 Gmail 帳號。若使用了其他帳號建立的資料夾，先確認部署帳號有權限；個人版建議由部署帳號自己建立。

### 工作表標頭錯誤

檢查 `業務公文管理` 第一列的 10 個欄名、順序與標點，並確認沒有合併儲存格。先複製一份工作簿備份，再修正欄名；不要自行刪掉系統索引表。

### Tasks 清單載入失敗或沒有顯示任務

先直接開 [Google Tasks](https://tasks.google.com/) 並確認同一 Gmail 帳號下有 `消防`。清單可以由系統建立；若 API 仍失敗，查看 Apps Script「執行項目」錯誤，再核對 Tasks API 進階服務與 Cloud API。

若在手機 Google Tasks App 將這份清單改名，系統會嘗試把原清單改回 `消防`，保留其中任務；如果清單整份遭刪除，系統會重新定位同名清單，找不到時建立空清單。刪除後的任務無法由 Apps Script 還原，請先檢查 Google Tasks 的垃圾桶／復原功能（若帳號介面提供），或從試算表案件卡片重新同步案件任務。

若更新案件時看到「專屬資料夾位於 Google Drive 垃圾桶中」，請先在 Drive 垃圾桶找到該案件資料夾並選「還原」，再回 Web App 重試；程式會在上傳前阻止寫入垃圾桶內的資料夾，避免附件被存入不可見位置。

### 手機開啟要求登入、出現 403 或進錯帳號

用正式 `/exec` 網址，不要用 `/dev`。在瀏覽器切換到部署 Gmail；若同時登入多個帳號，開私人瀏覽視窗只登入此帳號再試。確認正式部署仍是「執行身分：我」和「存取：只有我自己」。

### 手機 Google Drive App 顯示「無權限查看子資料夾」

Web App 和 Drive App 可能使用不同的登入帳號。案件資料夾只授權給建立母資料夾的個人 Gmail；請依序排查：

1. 在 Web App 頂端確認登入的是部署用 Gmail。
2. 打開手機 Google Drive App，點右上角頭像，切換成同一個 Gmail。
3. 返回「消防小本本」，重新點案件卡片的「開啟資料夾」。
4. 若仍跳到另一個帳號，先在 Drive App 的帳號選單切換正確帳號，再從案件卡片重開連結；也可以把資料夾連結貼到已登入正確 Gmail 的 Safari 或 Chrome 開啟。
5. 如果正確帳號仍無權限，確認母資料夾是由部署用 Gmail 建立且仍存在，再確認案件子資料夾位於該母資料夾中。

不要用「知道連結的任何人」來排除個人帳號切換問題。若 Web App 能開、只有 Drive 連結無法開，通常是 Drive App/瀏覽器目前選用的帳號不同。

### 程式已更新但手機看到舊畫面

Apps Script「部署」→「管理部署作業」→編輯既有部署→選「新增版本」→部署。接著在手機重新載入 `/exec`；不要只按儲存而忘記發布新版本。

### 操作紀錄修復（網路中斷後顯示仍在處理）

建立和更新送出時會帶同一個 clientRequestId；前端先檢查含正式 ID 的完整 JSON 大小，確認未超限後才保存重送狀態。短期快取保存成功回應 10 分鐘，隱藏的 _操作紀錄表最多 1,000 筆；舊紀錄由每日觸發器清理，新寫入即將超過容量時才修剪。相同 ID 的已完成重送會回傳原結果；尚未確認的操作會阻止再次寫入，避免重複案件或重複進度。

若頁面提示「曾開始但尚未完成」：

1. 重新載入 Web App，先用主旨或資料 ID 確認案件是否已建立；若案件已存在，不要用新表單重建。
2. 在試算表選「檢視」→「隱藏的工作表」→ _操作紀錄，依更新時間找到最近的記錄，查看 operation、state、stage、資料 ID 和列號。
3. 建檔若在主表已有資料，重新送回同一筆內容會依資料 ID 恢復結果；若沒有資料但狀態仍是 PENDING，先檢查母資料夾是否有新子資料夾或附件。
4. 更新若 stage 是 SHEET_COMMITTED 開頭，重送同一內容會回傳案件現況並補更新索引／Tasks。若仍是 PENDING 且主表時間軸已出現本次內容，切勿再新增同一段進度。
5. 只有在確認主表沒有提交、案件資料夾也沒有本次附件後，才可將該列 state 改為 FAILED，讓同一個瀏覽器表單安全重試。若無法判斷，保留紀錄並先檢查 Drive 和主表，不要直接刪除操作紀錄。

不要刪除或改名 _操作紀錄 工作表。每月試算表備份也會包含這張表；它只保留短期的冪等狀態，不保存附件 Base64。

### 附件上傳失敗或圖片沒有變小

附件原始資料合計最多 5 MiB，整包序列化 JSON（含 Base64）最多 6 MiB。前端送出前會用 Blob 計算 JSON 位元組數，超限時顯示「檔案合計過大，請分批上傳或只留重點附件」。照片會用 Canvas 壓縮；HEIC/HEIF 若無法轉成 JPEG 會停止送出，不會靜默上傳原始大檔。可先在 iPhone 將照片轉存為 JPEG，或將大文件直接放進案件 Drive 資料夾，再於進度紀錄註明。

### 儲存進度時超過 50,000 字元

Google 試算表單格有字數限制。先將完整 H 欄時間軸複製並另存至該案件 Drive 資料夾，再以「全文手動修改」保留近期內容並移除較舊段落，最後重試。系統在超限時會拒絕儲存，並在檢查通過前不會上傳該次附件。

### 建檔後出現 Tasks 同步警告

案件可能已寫入試算表與 Drive，只是 Tasks 失敗。先用資料 ID 在主畫面確認案件已存在，再按卡片「同步到 Tasks」重試；不要立刻重送建檔表單，以免重複建立案件。

### 查看執行錯誤

在 Apps Script 左側選「執行項目」，打開失敗的執行記錄查看函式、時間與錯誤訊息。常見原因是尚未授權、API 未啟用、Drive ID 錯誤、欄位標頭不符或 Google 服務暫時限流。
